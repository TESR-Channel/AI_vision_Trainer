1 · Choose Your Task

What should the AI do? You can switch anytime — your photos are kept.

🎯 Object Detection — what & where

You draw a box on each photo; the AI learns to find the object, draw its box and report its center position (x, y) live — ready for robots and automation. Tracks one object per frame. Recommended: 40+ labeled photos per class (80+ is noticeably better).

🏷 Classification — what is it

The fastest path: no boxes to draw. The AI names what it sees in the whole frame. Great for sorting, go/no-go checks and quick demos. Recommended: 30+ photos per class (60+ is noticeably better).

2 · Classes

What should the AI learn to tell apart? At least 2 classes. Then press + Background and capture what it must IGNORE: the empty scene, your hands moving in view, other things on the table — no boxes needed. This is what stops hands being called a lemon.

Project file — save all photos + labels as one .zip and continue any time. Add a new object later without redoing the old ones: load the project back, add the new class, capture its photos, press Train again — then re-download the YOLO dataset so the offline model learns the new class too. Every export zip (Download Model, Download Dataset) also contains the project — Load Project accepts those zips too.

3.5 · Auto Data Augmentation (optional)

Only a few photos? Generate more right here in the browser — flips, lighting and zoom variations of your examples (boxes are transformed along with the image in detection mode). Generated ones are marked ✨ and can be removed anytime.


In detection mode only labeled photos are augmented: the object is moved to new positions, zoomed, mirrored and relit, with its box moved along — position variety is what teaches the box model WHERE. Training also makes its own position-shifted copies for the box model automatically.

5 · Test Live & Export

Point the camera at your objects — predictions update in real time

Two gates decide "none": low confidence (threshold above) OR the frame does not look like any of your training photos (feature similarity, learned automatically at training time).
Every object: each cell of a 7×7 (or 14×14 for small, close parts) grid over the frame says whether an object is centred there, which class and its box — so every trained object in view gets its own box, center (x, y) and id (#1, #2 …), each smoothed on its own. It was trained on automatic mosaics of your photos (several objects, also half out of frame). This is exactly what model.onnx outputs as output0 on the device and in ROI Studio.
Precise scans 25 crops per frame to find the object wherever it is (~1 fps); Fast uses the trained box model (real-time but coarser — needs training photos with the object in many positions). Both show a crosshair at the object's center in pixels — the numbers a robot arm or conveyor system needs. One object per frame; for multi-object production systems, use the TESR Desktop Trainer (YOLO).
One flow: Download Model → on your computer: install, python predict.py → python export.py --target pi or --target jetson → copy to the board, install, python predict.py. Open START_HERE.md in the zip.



ONNX only = model.onnx (ONNX → TensorRT, course chapter 6: trtexec --onnx=model.onnx --fp16). Input images [1,3,224,224] RGB 0..1; detection adds a YOLO-style output0. Send to ROI Studio puts the model straight into ROI Studio's My models — draw an ROI, choose YOLO detect/classify, pick the model.

✂ Crop boxes

Cuts every box of one class out of its photo as a new photo — e.g. every terminal block — so a second AI can learn the small parts inside (two-stage QC: AI #1 finds the part → AI #2 finds the screws in the crop).



Added on every side, as a share of the box's width / height (10% = 20% wider), never past the photo edge. Rotated boxes use their upright extent. Generated ✨ photos are not cut.
